Вы работаете в крупной компании, которая строит систему на основе микросервисной архитектуры. 
Вам как DevOps-специалисту необходимо выдвинуть предложение по организации инфраструктуры для разработки и эксплуатации.

# Задача 1: Кластеризация

Предложите решение для обеспечения развёртывания, запуска и управления приложениями. Решение может состоять из одного или нескольких программных продуктов и должно описывать способы и принципы их взаимодействия.
 
Решение должно соответствовать следующим требованиям:
- поддержка контейнеров;
- обеспечивать обнаружение сервисов и маршрутизацию запросов;
- обеспечивать возможность горизонтального масштабирования;
- обеспечивать возможность автоматического масштабирования;
- обеспечивать явное разделение ресурсов, доступных извне и внутри системы;
- обеспечивать возможность конфигурировать приложения с помощью переменных среды, в том числе с возможностью - безопасного хранения чувствительных данных таких как пароли, ключи доступа, ключи шифрования и т. п.
Обоснуйте свой выбор.

# Реализация предлагается в Kubernetes

Стандарт индустрии. Kubernetes — самый распространённый оркестратор контейнеров, поддерживаемый всеми крупными облачными провайдерами (AWS EKS, GCP GKE, Azure AKS, Yandex Managed Kubernetes).

### Требование	

#### Поддержка контейнеров	
- Container Runtime Interface (CRI):  containerd, CRI-O, Docker
#### Обнаружение сервисов и маршрутизация	
- Обнаружение через объект Service и DNS-имена (CoreDNS). Внутренняя балансировка — kube-proxy. Внешний трафик — Ingress Controller (NGINX/Traefik) или Gateway API.
#### Горизонтальное масштабирование	
- Объект Deployment (поле replicas), ручное (kubectl scale) и автоматическое изменение числа узлов (Cluster Autoscaler).
#### Автоматическое масштабирование	
- HPA/VPA (по CPU, памяти, кастомным метрикам из Prometheus), KEDA (события очередей Kafka/RabbitMQ).
#### Разделение внешних и внутренних ресурсов	
- Типы сервисов: ClusterIP (внутри кластера), NodePort/LoadBalancer, изоляция трафика — NetworkPolicy, разделение сред — Namespaces.
#### Конфигурирование через переменные среды	
- Нечуствительные данные — ConfigMap. Чувствительные данные — Secret и внешнее хранилища HashiCorp Vault. Данные передаются в приложения как переменные среды (env/envFrom).
#### Безопасное хранение секретов
- Vault, Sealed Secrets, External Secrets Operator, шифрование etcd

### Обоснование
	
Расширяемость. CRD (Custom Resource Definitions) и операторы позволяют добавлять собственные абстракции и автоматизировать управление сложными приложениями.

Экосистема. Огромное количество готовых инструментов: Helm (пакетный менеджер), Prometheus (мониторинг), Loki (логи), Istio/Linkerd (service mesh), ArgoCD/Flux (GitOps).

Отказоустойчивость. Self-healing: Kubernetes автоматически перезапускает упавшие контейнеры, заменяет недоступные Pod'ы и перераспределяет нагрузку.

Портативность. Одинаковые манифесты работают в любом облаке и on-premise, что снижает vendor lock-in.
